0. Резюме проекта
Цель. Создать систему, которая принимает художественную книгу и автоматически формирует многоголосую аудиокнигу с постоянными голосами персонажей, эмоциональной режиссурой, корректным определением говорящего, контролем произношения и автоматической проверкой качества.
Ключевое архитектурное решение. ElevenLabs используется как основной speech-движок: Voice Design v3 — для кастинга и создания персонажных голосов; Eleven v3 Text-to-Dialogue — для многоголосых сцен; обычный Eleven v3 / Multilingual v2 — для одиночных реплик и повествования там, где это даёт лучший результат. Вся бизнес-логика остаётся независимой от провайдера через TTSAdapter.

1. Цели, границы и пользовательский сценарий
1.1. Цель продукта
Преобразование EPUB/FB2/TXT в полноценную многоголосую аудиокнигу.
Отдельный постоянный голос рассказчика и постоянные голоса персонажей.
Автоматическое определение говорящего, пола/возрастной категории и речевого профиля без выдумывания неизвестных фактов.
Художественная режиссура реплик с учётом текущей сцены и скрытого/выраженного эмоционального состояния.
Корректное произношение имён, омографов, аббревиатур, чисел и иностранных терминов.
Автоматический контроль качества и точечная перегенерация без повторной генерации всей книги.
Экспорт по главам и единым M4B-файлом.
1.2. Основной пользовательский поток
Пользователь загружает книгу.
Система извлекает структуру и анализирует персонажей.
Пользователь просматривает Character Bible и исправляет неоднозначности при необходимости.
Casting Director формирует voice brief; ElevenLabs Voice Design создаёт несколько кандидатов.
Пользователь или автоматический audition-модуль выбирает голос; voice_id фиксируется (LOCK).
Генерируется одна-две тестовые сцены, после чего пользователь утверждает стиль.
Система режиссирует и озвучивает книгу по сценам/блокам.
QC проверяет текстовую точность, идентичность голоса и акустическое качество; неудачные сегменты перегенерируются.
Audio Engine собирает главы и финальный M4B.
1.3. Вне scope первой версии
OCR сканов как часть основного pipeline — допускается отдельный preprocessing-модуль.
Автоматическая публикация книги в коммерческих магазинах.
Музыкальное оформление и саунд-дизайн уровня радиоспектакля.
Клонирование голоса реального человека без подтверждённых прав/согласия.
2. Архитектурные принципы
Принцип
Требование
Structured first
Агенты возвращают JSON по схеме, а не свободный текст.
Persistent memory
Character Bible, voice_id и события живут в БД, а не только в контексте LLM.
Voice lock
После утверждения голос персонажа не меняется автоматически.
Human override
Любое художественное решение можно поправить вручную на уровне реплики/сцены/персонажа.
Provider abstraction
Вся логика выше TTS работает через единый TTSAdapter.
Idempotency
Повторный запуск не должен повторно генерировать неизменившиеся сегменты.
Traceability
Для каждого аудиофрагмента хранится полная трассировка: текст, модель, voice_id, настройки, seed, версия prompt.
Fail safe
Неоднозначность маркируется unknown/review, а не заполняется выдуманным значением.

Ключевая граница ответственности. LLM отвечает за интерпретацию; ElevenLabs — за исполнение; код — за состояние, ограничения, очереди, retries, кэш и валидацию.

3. ElevenLabs-first стратегия
3.1. Почему ElevenLabs — основной backend
Voice Design v3 позволяет создавать голос из текстового описания, включая возраст, пол, акцент, тон, темп и стиль; один запрос формирует три preview-кандидата.
Созданные Voice Design v3 голоса совместимы с Eleven v3 и audio tags.
Eleven v3 поддерживает эмоциональные/режиссёрские audio tags и natural multi-speaker dialogue.
Text-to-Dialogue позволяет передавать последовательность реплик разных voice_id в одном запросе, сохраняя контекст разговора.
Русский поддерживается Eleven v3.
3.2. Ограничения, которые сразу учитываются в проекте
Ограничение
Архитектурная реакция
Text-to-Dialogue рекомендуется держать ≤ 2000 символов суммарно
Диалоги режутся по смысловым мини-сценам, а не по фиксированному числу символов.
Генерация недетерминирована
Сохранять seed, параметры и лучший получившийся audio artifact; QC + controlled retry.
Eleven v3 не использует SSML break tags
Паузы задавать контекстом, пунктуацией/audio tags; точные межсегментные паузы добавляет Audio Engine.
Voice Design experimental
Всегда проводить audition на нескольких типах реплик и фиксировать только прошедший голос.
PVC и Eleven v3 имеют ограничения совместимости
Для v3-персонажей в базовой архитектуре использовать Voice Design / совместимые voices; PVC не делать обязательным механизмом.
Default voices могут меняться/исчезать
Не строить ключевой каст на нестабильных default voice assumptions; хранить provider voice metadata и проверять доступность.

5.1. Идентификаторы
Все сущности получают стабильный UUID/внутренний ID сразу после парсинга.
Исходный текст не перезаписывается: любые нормализации хранятся отдельно.
Любой сгенерированный audio segment должен ссылаться на конкретный utterance_id.
5.2. Speaker types
Тип
Пример обработки
NARRATOR
Базовый narration voice.
CHARACTER
Постоянный character voice_id.
INNER_THOUGHT
Тот же voice_id, другая режиссура/постобработка.
LETTER / DIARY
Может читаться персонажем или рассказчиком согласно контексту.
PHONE / RADIO / ANNOUNCEMENT
Голос персонажа + опциональный безопасный постэффект.

Особая маркировка; может требовать отдельного synthetic voice или narration.
UNKNOWN
Не генерировать автоматически ниже порога confidence без повторного анализа/ручной проверки.

6. Агенты и их контракты
6.1. Book Analyst
Выделяет персонажей, aliases, отношения, социальные роли, пол/возрастную категорию при наличии доказательств.
Формирует chapter/scene summaries и глобальную story memory.
Не назначает voice_id и не управляет TTS.
Каждый inferred-факт хранит confidence и evidence references.
{
  "character_id": "char_007",
  "canonical_name": "Анна Сергеевна",
  "aliases": ["Анна", "Аня"],
  "gender": {"value": "female", "confidence": 0.99},
  "age_band": {"value": "25-30", "confidence": 0.72},
  "personality": ["reserved", "intelligent", "anxious"],
  "evidence": ["ch03_p18", "ch04_p07"]
}
6.2. Speaker Attribution Agent
Получает current scene + ближайший контекст + список доступных character_id.
Не имеет права создавать новый character_id без отдельного entity-resolution шага.
Возвращает speaker_id, confidence, evidence и reason_code.
Низкий confidence запускает second-pass или manual review.
Confidence
Действие
≥ 0.90
Автоподтверждение, если нет конфликтующих сигналов.
0.70–0.89
Second-pass + Continuity check.
&lt; 0.70
Manual review либо расширенный контекст.

Пороговые значения стартовые и должны быть откалиброваны на реальном корпусе.
6.3. Character &amp; Continuity Agent
Объединяет aliases и предотвращает дубли персонажей.
Следит за сохранностью пола, роли, voice_id и базового speech profile.
Учитывает flashback/aging как явные временные состояния, а не как создание нового персонажа.
Не меняет LOCKED voice без explicit change request.
6.4. Casting Director
Преобразует Character Bible в provider-neutral Voice Brief.
Формирует ElevenLabs Voice Design prompt и audition pack.
Запрашивает три preview-кандидата через Voice Design.
Сравнивает кандидатов по character fit, разборчивости, выразительности и различимости с уже утверждёнными персонажами.
После выбора сохраняет voice_id и блокирует автоматическую замену.
6.5. Scene Director
Определяет не «эмоцию героя вообще», а подачу конкретной реплики.
Разделяет internal_state и expressed_state.
Определяет intent, primary/secondary emotion, intensity, tempo, delivery notes, допустимые Eleven v3 audio tags.
Работает на уровне сцены, а не изолированной строки.
6.6. Pronunciation Agent
Создаёт контекстный pronunciation dictionary.
Разрешает омографы, имена, топонимы, иностранные слова, аббревиатуры, даты и числа.
Для Eleven v3 допускает IPA-подход там, где он поддерживается; точный способ должен находиться внутри ElevenLabs Adapter, а не в бизнес-логике.
Не выполняет глобальные replace без проверки контекста.
6.7. Quality Review Agent
Получает числовые QC-метрики и контекст только для спорных сегментов.
Не слушает/перегенерирует всё подряд без причины.
Формирует одну из команд: PASS / RETRY_SAME / RETRY_DIRECTED / MANUAL_REVIEW / FALLBACK_BACKEND.

11.3. Provider-neutral параметры
Не хранить бизнес-логику в терминах только stability/style/similarity_boost.
Performance Plan остаётся семантическим; adapter переводит его в audio tags, voice settings и формат запроса.
Все фактические provider parameters сохраняются в GenerationRecord для воспроизводимости.
12. Сегментация и Text-to-Dialogue
12.1. Блок диалога
Граница формируется по смыслу и сцене.
Целевой суммарный объём inputs[].text — не более ~2000 символов на запрос Text-to-Dialogue.
Не разрывать эмоциональный обмен посреди пары вопрос–ответ без необходимости.
При большом диалоге создавать последовательность dialogue_block_N и сохранять переходное состояние.
dialogue_block_014
  context_before: short summary
  lines:
    1. speaker=anna, voice_id=...
    2. speaker=mikhail, voice_id=...
    3. speaker=anna, voice_id=...
  total_text_chars &lt;= target_limit
  seed = stored
  output -&gt; audio_artifact
12.2. Narration между репликами
Нужно benchmark-решение: либо включать короткие narrator-вставки в один dialogue request с narrator voice_id, либо генерировать их отдельно. Выбор определяется A/B-тестом плавности переходов. Архитектура должна поддерживать оба режима.

Quality Review Agent уточняет delivery/audio tags.
4
Разбить блок на меньшие части либо изменить режим single/dialogue.
5
Manual review или fallback backend — только если он подключён и совместим по voice identity.

Важно. Удачный audio artifact никогда не перегенерируется без изменения входных данных или явного запроса. Генеративная недетерминированность делает сохранение лучшего результата обязательным.

14. Аудиомонтаж и экспорт
Master storage в WAV/FLAC; пользовательский экспорт MP3 и M4B.
Паузы между независимыми сегментами добавляет Audio Engine в миллисекундах.
Не выравнивать whisper/shout до одинакового мгновенного уровня; loudness normalization выполняется с сохранением художественной динамики.
Chapter markers, author/title/cover metadata включаются в M4B.
Точечная регенерация заменяет только соответствующий segment и пересобирает затронутую главу/финальный контейнер.

22. Критерии приёмки
1. EPUB/FB2/TXT успешно импортируется без потери глав и абзацев.
2. Система формирует редактируемый Character Bible.
3. Speaker attribution работает с confidence и review path.
4. Для персонажа можно получить 3 Voice Design preview и зафиксировать выбранный voice_id.
5. После LOCK один персонаж использует один и тот же voice_id во всех последующих генерациях.
6. Система генерирует preview сцены до запуска полной книги.
7. Поддерживается Eleven v3 Text-to-Dialogue для многоголосого блока.
8. Суммарный размер dialogue request контролируется и не превышает configured safe limit.
9. Каждый audio segment имеет GenerationRecord.
10. ASR QC выявляет явные пропуски/повторы и отправляет сегмент на controlled retry.
11. Поддерживается точечная перегенерация utterance/scene/chapter.
12. Процесс возобновляется после рестарта без потери утверждённых сегментов.
13. Финальный экспорт формирует MP3 по главам и M4B с метаданными.
14. Пользователь может вручную исправить speaker, voice, pronunciation и delivery.

Приложение D. Актуальные допущения ElevenLabs и источники
Факты ниже проверены по официальной документации ElevenLabs на 19.09.2026. Так как API и модели меняются, эти ограничения должны быть вынесены в конфигурацию и повторно проверяться перед production-релизом.
Voice Design: Voice Design генерирует три preview; поддерживает описание возраста, пола, акцента, тона, темпа и стиля; Voice Design v3 совместим с Eleven v3. Также отмечено, что Voice Design остаётся experimental. https://elevenlabs.io/docs/eleven-creative/voices/voice-design
Text to Dialogue: Eleven v3; multi-speaker; рекомендуется ≤2000 символов суммарно в inputs[].text на запрос; output недетерминирован, seed повышает стабильность. https://elevenlabs.io/docs/overview/capabilities/text-to-dialogue
Text to Speech / Eleven v3: Eleven v3 поддерживает audio tags для эмоций/манеры/реакций и 70+ языков, включая русский; v3 не поддерживает SSML break tags. https://elevenlabs.io/docs/eleven-creative/playground/text-to-speech
Voices overview: Voice Library, Voice Design, cloning и языки; Generated Voices подходят для character/storytelling. Документация также предупреждает об изменениях default voices. https://elevenlabs.io/docs/overview/capabilities/voices
Voice settings API: Provider settings включают stability, similarity_boost, style, speed и speaker boost; их следует хранить в GenerationRecord, но не делать частью provider-neutral доменной модели. https://elevenlabs.io/docs/api-reference/voices/settings/update
Конфигурационное требование. provider_limits.json должен содержать лимиты и feature flags ElevenLabs, чтобы изменение документации не требовало переписывания доменной логики.

Итоговые архитектурные решения
1. ElevenLabs — основной TTS provider; система остаётся provider-agnostic выше уровня adapter.
2. Voice Design — инструмент Casting Director, а не механизм генерации каждой реплики.
3. Каждый утверждённый персонаж получает LOCKED voice_id.
4. Eleven v3 Text-to-Dialogue — основной режим для коротких многоголосых сцен; блоки режутся семантически и контролируются по размеру.
5. Scene Director формирует provider-neutral Performance Plan; ElevenLabs Adapter переводит его в допустимые audio tags/settings.
6. Точный контроль пауз между сегментами выполняет Audio Engine; не полагаться на SSML break в Eleven v3.
7. QC состоит минимум из ASR round-trip, speaker consistency и acoustic checks.
8. Удачные результаты кэшируются и никогда не перегенерируются автоматически без необходимости.
9. Перед full-book generation обязательны casting audition и preview нескольких сцен.
10. MVP строится по вертикальному срезу от книги до 10–15 минут готового аудио, после чего система масштабируется.
